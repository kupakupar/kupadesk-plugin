# KupaDesk 更新入口

当前版本为 032，公开入口和目标运行核心均为 0.0.32。在 Magpie「插件 → 已安装」中单独更新 KupaDesk，再刷新页面即可。

032 修复进阶设置的展开布局：右侧编辑卡片先伸展至与左侧核心库齐高，超出内容再由整个编辑区滚动，移除进阶设置内部的小滚动框。极矮窗口继续采用整页滚动，保存按钮保持可达。仅修改页面样式；注入、授权、心跳、绑定、保存和同步逻辑沿用 031。

031 增加每份核心的适用 Agent 设置和只读状态自检，新建核心默认前置。云端核心、Agent 范围、注入模式、Chat 角色和供应商筛选统一使用页面主题下拉菜单，支持亮暗主题、键盘、长列表与小窗口；修复窄窗口保存栏遮挡选择框。已有明确注入模式与模型绑定保留；公开更新入口、签名助手、授权续期、同步及私有分发方式沿用原来实现。

以下为历史版本记录，其中版本号描述该次发布时的状态。

030 补回 Magpie 插件列表和页面标签的 KupaDesk 图标，图标随公开入口一起分发，不依赖私有核心下载或授权状态。在「插件 → 已安装」中单独更新 KupaDesk 即可；本次入口为 0.0.30，运行核心目标仍为 0.0.29。授权、核心注入、更新加载和同步逻辑保持原样。

029 将恢复授权与更新分开：当前授权有效、运行核心就绪时直接返回编辑页；授权需要恢复时只续期当前设备，不检查版本清单或下载代码。缺少核心时明确提示使用独立的「准备／更新核心」。首次激活仍会准备必需核心；已有有效授权时可在云端页单独选择「更换卡密」。

在 Magpie 中单独更新 KupaDesk 后刷新页面，公开入口和运行核心目标为 0.0.29。核心、绑定、登录及同步机制保持原来方式；无需卸载或重新安装。

028 修复本机页面服务退出后无法恢复、复用服务随旧宿主退出，以及小高度窗口裁切内容且不能滚动的问题。页面服务会后台恢复，已加载页面中的未保存草稿保留；窗口变矮后可滚动到正文和保存按钮。授权续期改为提前发起、限制单次续期等待并保留重试时间，避免一次连接卡顿耗尽租约。租约有效期和停卡规则不变。

在 Magpie「插件 → 已安装」中检查更新并单独更新 KupaDesk，再刷新 KupaDesk 页面。公开入口和运行核心都应显示 0.0.28。仍然只公开更新壳，核心经原卡密渠道私有分发。

027 在请求诊断中加入“显示未绑定请求”开关，默认显示，关闭后同步过滤列表与顶部摘要；拒绝和检查失败仍显示。点击“保存设置”可记住选择。更新后的授权恢复阶段改为中性等待提示，自动恢复，不再误报需要重新激活。租约时长、心跳、授权校验、核心注入和同步逻辑不变。

026 目标核心增加每份核心的前置、追加、替换三种模式，兼容 Claude Desktop 的映射模型名，并移除挤占编辑空间的顶部版本横幅。已有核心保留原模式，新建核心默认追加。更新壳和签名助手加载方式保持原样，运行核心仍经卡密授权后私有分发。

025 修复更新过程中界面停留在 `not_ready` 的问题：等待页会核对目标、下载和运行状态，界面真正准备完成后自动恢复，并提供重试与授权入口。私有运行核心继续使用 024，原注入、授权、心跳、保存和同步实现不变。

024 将绑定核心放在原系统指令之前，保留原内容和角色；兼容旧注入标记，重试保持单份。前置改变排列顺序，不提高指令权限。工具、思考参数、历史以及授权、心跳和同步逻辑保持原样。

此目录只包含公开更新壳。激活助手由服务端签名下发，私有运行核心凭有效卡密获取；鉴权与注入实现不在此仓库发布。

已有用户直接通过 Magpie「检查更新」更新；新用户也可安装此入口。更新或安装后，在 KupaDesk 页面输入卡密即可启用，无需 GitHub 账号，也无需单独运行安装器。现有核心、模型绑定、登录和同步设置保留。

公开入口只校验、加载服务端签名的激活助手，不包含设备授权协议或注入实现。激活助手不含核心注入和私有运行界面；私有核心仍凭有效卡密与已绑定设备下载。未授权时不注入核心，也不修改原请求的工具、思考参数和历史。

入口更新与私有核心准备是两个阶段；以 KupaDesk 页面显示的运行核心版本和状态为准。未授权、下载失败或核心未就绪时，不会显示核心已经成功升级。此入口不改动 Magpie 官方程序，也不替换供应商连接。
