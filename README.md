# KupaDesk

## 0.0.14

修复 Codex Responses Lite 的工具声明被提示词清理误删的问题。Codex 0.163.0-alpha.11 会把工具放在 `input` 中 `role: developer` 的 `additional_tools` 项里；这些项没有消息正文。插件现在只清理普通 `system` / `developer` 消息，原样保留工具声明和其他结构化输入项。

保留提示词追加、重复注入检查、模型绑定、原供应商连接、页面、诊断及加密同步逻辑，安装入口仍为 `github:kupakupar/kupadesk-plugin`。无需迁移设置，也不修改 Magpie 或 Codex 的官方程序。

验证：32 项注入、模型目录、设置同步及诊断测试，7 项页面资源测试；使用未修改的官方 Magpie 0.1.1307、Codex 0.163.0-alpha.11 捕获的 Standard / Lite 工具声明，在隔离配置与本地模拟供应商中验证 16 个组合（停用插件、0.0.13、0.0.14、同步中间件回退 × Chat / Responses × Standard / Lite）。旧版 Lite 的 11 个工具被误删为 0；新版保留工具声明，并通过自定义工具调用与结果回传检查。未调用真实模型、执行工具代码或修改正在使用的配置；尚未替换正式插件进行桌面会话验证。

## 0.0.13

只修复页面刷新相关的两项问题：刷新开始后阻止重复点击，导航未完成时在 8 秒后恢复重试；页面 SDK 的请求编号加入每次加载独立的随机前缀，避免刷新前的迟到响应被新页面误认为当前请求。保留官方 SDK 的父窗口来源校验、方法、主题处理与 options 数据结构。

在原生 Wails/WebView2 沙箱窗口复现：延迟旧 options.get 的错误回包，0.0.12 页内刷新会错误结束新页面的初始化；0.0.10 重建 iframe 的方式正常；本版正确忽略旧回包并继续加载当前设置。另有连点 25 次导致 25 次导航的回归用例，本版只发起 1 次。

最终版本通过约 10 分钟、120 轮原生混合测试，覆盖刷新、连续点击、重建 iframe、亮暗切换和更新资源后加载新版页面。上述复现为页面初始化异常；整个 Magpie 窗口卡死、WebView 浏览器进程占满一个 CPU 核的现场尚未独立复现，不能据此认定该整窗故障已彻底修复。

注入、模型匹配、目录同步、诊断与加密设置同步实现均未修改，设置结构保持不变。升级继续沿用 `github:kupakupar/kupadesk-plugin` 安装入口，保留提示词、模型绑定、登录与云端同步设置。

验证：`node tests/page-bridge-refresh.cjs`；`node tests/page-refresh.cjs <已有 jsdom 路径>`；`tests/native-refresh-host` 使用已安装的 Go 与原有 Wails 依赖构建隔离窗口，测试脚本只操作指定诊断端口的合成数据。CPU 监测使用现有 Python psutil，不纳入插件运行时依赖。

## 0.0.10

增加请求诊断：正常显示模型名称、提示词名称、实际供应商和是否确认加入提示词；模型 ID、入口检查和宿主检查收进「技术详情」。只显示本机真实请求，未收到请求时显示等待状态；独立测试记录不随插件发布。继续使用同一 GitHub 安装入口升级，保留提示词、模型绑定和云端同步设置。

注入函数、匹配规则、请求索引、模型目录同步与加密设置同步均沿用 009。完成回调只观察结果；通过客户端收到的回复 ID 唯一对应本机 `usage.jsonl`，不按时间邻近猜测归属。并发请求分开记录，重复 ID 或不一致记录显示无法确认。没有增加 `onProvider`、响应改写、工具声明或供应商控制。

诊断不记录提示词/对话正文、工具参数、回复内容、端点、账号或凭据；仅保留当前进程内有限条元数据，并沿用现有目录快照把这些元数据提供给页面。读取用量文件为后台只读、分块读取。未开启本机用量记录、回复无 ID、插件完成回调被宿主丢弃或超过其采集上限时，实际供应商可能无法确认。宿主接受的请求包含提示词不等于供应商最终收到了未变动正文，也不等于模型遵循提示词。

独立预览：`python tests/preview-host.py --port 4692`。使用单独的设置副本，诊断示例来自未修改官方宿主与本地模拟供应商的隔离测试，保存不会写回现用 009。

验证：`node --test tests/diagnostics.test.mjs`；使用 Bun 执行原有注入和同步测试；`python tests/official-host.py --magpie <官方程序> --bun <已有 Bun>` 验证四种协议与真实宿主回复 ID 关联；`node tests/page-diagnostics.cjs <已有 jsdom 路径>` 验证界面与草稿隔离。

开发预览：在此目录执行 `python tests/preview-host.py --port 4691` 后，打开 `http://127.0.0.1:4691/`。预览首次从当前 Magpie **只读复制**提示词与绑定、模型目录快照；不读取供应商凭据或同步口令，不启动注入运行时。预览保存仅写入相邻的 `kupadesk-009-preview-private` 目录，绝不写回当前 Magpie。

Magpie 原生提示词库插件。请求沿用原供应商；支持多份本地提示词、模型搜索多选和供应商模型目录自动同步。

在 Magpie 的插件安装框输入：

```text
github:kupakupar/kupadesk-plugin
```

各设备使用同一 GitHub 安装入口升级插件代码；已有提示词、模型绑定和开关通过下述加密同步保留。插件名称保持 `kupadesk`，页面标题为 KupaDesk。

通过 Magpie 现有的加密同步同步提示词名称、全文、模型绑定和开关。请在各设备配置同一同步账户和口令，并开启供应商同步。插件仅处理 Magpie 已下载并校验的本机加密同步缓存，不另外发送网络请求。

同步冲突保留为禁用且未绑定模型的副本，避免覆盖已有提示词；写入前自动备份到 Magpie 配置目录的 `kupadesk-private-sync/backups`。未保存的页面草稿不会被后台刷新覆盖。

插件代码不含个人提示词、供应商凭据或同步口令；这些仅保留在本机配置与用户自己的加密同步文件中。

0.0.6 使用 Bun 请求钩子处理长上下文，并保留 Go 网关中间件作为后备；重复经过两条路径只保留一份提示词。模型匹配识别完整 ID、明确的推理强度后缀、供应商旧 ID、路由组名称，以及没有歧义的裸模型名。无法确定裸模型或组内不同成员应使用哪份提示词时会报错，请使用完整模型 ID 或给整个路由组绑定同一份提示词。

提示词编辑器支持每份 32768 个字符，粘贴超长内容不会被截断；超过字符数或 48 KiB 总设置预算时会阻止保存并提示。旧版已经截断后保存的内容无法自动恢复，请从原文补齐。

页面的请求检查只报告插件生成注入的结果，不读取或显示提示词正文。原供应商、模型和登录方式保持原配置。模型是否遵循指令仍取决于模型；官方宿主在两条插件路径均无法加载或均超时时仍会原样放行，这一行为不能由插件消除。

0.0.8 以 0.0.6 为基础，继续使用入口 `onRequest` 注入；未启用 0.0.7 的 `onProvider` 路由后匹配。界面仅保留 KupaDesk 标签页，不注册供应商内嵌面板或供应商菜单。

保存前会重新读取宿主设置。若其他页面或同步已更新设置，会停止保存并保留当前草稿，避免直接覆盖新内容。设置结构、提示词全文、模型绑定和加密同步实现沿用 0.0.6。此检查不是宿主事务锁，无法消除检查后同时发生的写入。
